二 · 完整方案

01 变更摘要

一句话

删除四档「界面材质」选择器，改为「跟随系统」单一默认 + 一个 app 内覆盖开关；把材质从用户选项降级为实现细节，把「可读性」提升为 app 的唯一承诺。

结果：渲染路径从 4 档 × 2 外观 × 5 层级 × 2 容器 × 3 系统状态 ≈ 240 条，收敛为「1 个基线 + 5 个固定层级偏移 + 1 次整体变换」，约 12 个常量。

02 为什么要改
  1. 四个不是四个主题。 它们只是「一根透明度轴上的三个刻度 + 一条版本兼容说明」。切换时其他视觉变量全不变，用户感受不到「换了主题」，只觉得「没变化」或「色差不对」。
  2. 维度混用。 前三档讲视觉效果，第四档讲工程策略；而 Liquid Glass 在 Apple 那边根本不是用户选项，是用 26 SDK 重编译自动获得的系统材质。
  3. 设计承诺不可兑现。 玻璃需要背后有内容可折射。设置窗口是透明 NSWindow，behindWindow 采不到有效内容，「更明显的背景虚化」物理上做不到；修到最后只能变成固定近白，名字就成了谎话。
  4. 层级各自实现材质。 窗口底带渐变、顶栏带整体透明度、卡片带半透明与三层高光 —— 每个容器各自抄一份数值，必然漂移。今晚的「中灰卡片 vs 近白窗口底（248 / 193，差 55 级）」就是结果。
03 目标模型

材质设计不是「四档 × 明暗 × 两端」，而是「一个基线 × 一组固定的层级偏移」。

维度取值允许改不允许改
档位取消由系统决定基线渲染方式层级差值
外观亮 / 暗基线 token 的两套值层级方向、层级差
层级L0 窗口底 / L1 顶栏 / L2 卡片 / L3 强调卡 / L4 控件只准固定偏移各自实现一套材质
容器NSPopover / 透明 NSWindow只提供「能否采样背景」标志各自抄一份色值
系统状态降低透明度 / 增强对比度整栈一次性变换每层各自判断
04 层级契约
层职责允许的效果与下一层的固定关系
L0 窗口底只给基色纯色；不叠渐变、高光、模糊基线
L1 顶栏只给边界1pt 分隔线 + 极弱阴影亮度 ±2%，不重复材质、不设整体透明度
L2 卡片只给抬升+亮度、1pt 描边、柔和阴影比 L0 高 2–3%，单调递增
L3 强调卡语义色唯一允许使用 tint亮度不低于 L2，色相独立
L4 控件交给系统app 不覆盖外观—

硬约束：L1−L0、L2−L0 的差值在两外观、两容器、所有系统状态下恒定。用户从 15 升到 26，感知到的应该是「整套栈一起换了质感」，而不是某几层悄悄变了。

05 容器能力降级

「跟随系统」不等于两端用同一套渲染。容器只声明一个能力标志：

  • 仪表盘（NSPopover）：能采样背景内容。macOS 26+ 用系统材质；15 及更早用兼容材质。
  • 设置窗口（透明 NSWindow）：不能采样背景内容。任何系统版本下都自动回退到实体近白基线。
  • 因此「玻璃虚化」不再作为一个可见选项存在，能力不足时静默降级，不向用户解释技术细节。
06 系统状态优先级
优先级条件结果
1（最高）系统「降低透明度」开启整栈强制实体，忽略一切其他设置与容器能力
2app 内「始终使用不透明背景」开启整栈实体，但系统开关关闭时可调回
3容器不能采样背景该容器单独回退到实体基线
4（默认）跟随系统26+ 系统材质 / 旧系统兼容材质

「增强对比度」只加粗描边与分隔线，不改层级亮度差；「减少动态效果」影响过渡动画，不影响颜色。

07 设置页信息架构
现在改后
卡片标题「界面材质」「外观与可读性」
四档分段选择器（实体 / 毛玻璃 / 高斯柔化 / 液态玻璃）一行状态说明「跟随系统 · 默认」+ 当前生效材质标签
每档一句副标题，维度不一一句统一说明：材质由 macOS 决定，文字对比度始终优先
「macOS 26 / 27」版本标签删除（版本适配是实现细节，不是用户需要知道的信息）
无新增开关「始终使用不透明背景」，带一句系统开关优先级的说明

文案统一改为描述「用户看到什么」。旧四档译名与版本说明从设置页移除，版本兼容信息可在「关于」页保留一行。

08 数据与迁移

采用方案 A：一次性迁移。现有偏好是已持久化的用户数据，直接删除会造成升级后外观突变。

  • 首次启动时读取旧值：旧值为「清晰实体」→ 新开关设为开启；其余三档 → 关闭；无旧值 → 关闭。
  • 迁移只执行一次，写入标记后不再读取旧键；旧键保留一个版本周期以便回滚，之后清除。
  • 诊断信息中的「界面材质」字段改为上报当前生效策略（跟随系统 / 不透明 / 能力降级），不再上报档位名。
  • 迁移过程对用户无感，不弹提示、不重置其他偏好。
09 实施步骤
  1. 建立单一材质 token 源：两套外观值、五个层级偏移、一组实体降级值。
  2. 新增容器能力标志，替换现有的「两套 backdrop 实现」分支。
  3. 把窗口底、顶栏、卡片、强调卡统一接到同一个出口；移除各自内部的渐变、整体透明度与重复高光。
  4. 加入系统版本分支：26+ 使用系统材质，旧系统使用兼容材质，分支只出现在一处。
  5. 把「降低透明度」与「始终不透明」合并成整栈变换，四个层共用。
  6. 改造设置页 UI 与文案，移除四档选择器与版本标签。
  7. 实现旧偏好一次性迁移，并更新诊断字段。
  8. 清理不再使用的枚举、译名与容器参数。
  9. 按验收标准逐项截图核对，再更新变更记录。

11 风险与边界
  • 最大视觉变化：仪表盘不再透桌面壁纸，浅色整体更平、更接近设置页。这是「统一」的代价，需要重新验收仪表盘观感。
  • 26+ 验证缺口：当前构建 SDK 为 26.2，系统材质 API 可编译；但实机是 15.8.2，真正的系统材质效果只能在 26 环境上验收，不能用编译通过代替。
  • 构建约束：部署目标仍是 macOS 14，版本分支必须做可用性门控；项目仍用 swiftc 直接构建，不引入新的包依赖。
  • 不做的事：不重绘 app 图标、不改状态栏图标、不加新主题色、不引入第三方材质库、不做 DMG、不定新版本号。
