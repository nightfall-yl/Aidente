二 · 完整方案

01 变更摘要

一句话

删除四档「界面材质」选择器，改为「外观」自动 / 浅色 / 深色 分段控件 + 「始终使用不透明背景」开关；把材质从用户选项降级为实现细节，把「可读性」提升为 app 的唯一承诺。本方案已于 6.1.1 / Build 22 落地：仪表盘三个容器恢复背景采样并叠加类液态玻璃静态层，macOS 26+ 改用系统 glassEffect(.regular)。

结果：渲染路径从 4 档 × 2 外观 × 5 层级 × 2 容器 × 3 系统状态 ≈ 240 条，收敛为「1 个基线 + 5 个固定层级偏移 + 1 次整体变换」，约 12 个常量。

02 为什么要改
  1. 四个不是四个主题。 它们只是「一根透明度轴上的三个刻度 + 一条版本兼容说明」。切换时其他视觉变量全不变，用户感受不到「换了主题」，只觉得「没变化」或「色差不对」。
  2. 维度混用。 前三档讲视觉效果，第四档讲工程策略；而 Liquid Glass 在 Apple 那边根本不是用户选项，是用 26 SDK 重编译自动获得的系统材质。
  3. 设计承诺不可兑现。 玻璃需要背后有内容可折射。设置窗口是透明 NSWindow，behindWindow 采不到有效内容，「更明显的背景虚化」物理上做不到；修到最后只能变成固定近白，名字就成了谎话。（此结论只约束设置窗口：仪表盘改用 borderless NSPanel 后已恢复 canSampleBackdrop = true，见 05。）
  4. 层级各自实现材质。 窗口底带渐变、顶栏带整体透明度、卡片带半透明与三层高光 —— 每个容器各自抄一份数值，必然漂移。今晚的「中灰卡片 vs 近白窗口底（248 / 193，差 55 级）」就是结果。
03 目标模型

材质设计不是「四档 × 明暗 × 两端」，而是「一个基线 × 一组固定的层级偏移」。

维度取值允许改不允许改
档位取消由系统决定基线渲染方式层级差值
外观亮 / 暗基线 token 的两套值层级方向、层级差
层级L0 窗口底 / L1 顶栏 / L2 卡片 / L3 强调卡 / L4 控件只准固定偏移各自实现一套材质
容器NSPopover / 透明 NSWindow只提供「能否采样背景」标志各自抄一份色值
系统状态降低透明度 / 增强对比度整栈一次性变换每层各自判断
04 层级契约
层职责允许的效果与下一层的固定关系
L0 窗口底只给基色纯色；不叠渐变、高光、模糊基线
L1 顶栏只给边界1pt 分隔线 + 极弱阴影亮度 ±2%，不重复材质、不设整体透明度
L2 卡片只给抬升+亮度、1pt 描边、柔和阴影比 L0 高 2–3%，单调递增
L3 强调卡语义色唯一允许使用 tint亮度不低于 L2，色相独立
L4 控件交给系统app 不覆盖外观—

硬约束：L1−L0、L2−L0 的差值在两外观、两容器、所有系统状态下恒定。用户从 15 升到 26，感知到的应该是「整套栈一起换了质感」，而不是某几层悄悄变了。

05 容器能力降级

「跟随系统」不等于两端用同一套渲染。容器只声明一个能力标志：

  • 仪表盘（borderless NSPanel / 独立仪表盘窗口 / 预览面板）：canSampleBackdrop = true，已恢复背景采样。macOS 26+ 用系统 glassEffect(.regular)；15 及更早用 NSVisualEffectView(.popover, .behindWindow) + AidenteGlassOverlay 自绘静态层（无真折射 / 色散）。
  • 设置窗口（标准 titled NSWindow）：canSampleBackdrop = false，任何系统版本下都走固定中性色阶的实体基线（亮 #F4F5F6 / 暗 #232326）。
  • 因此「玻璃虚化」不再作为一个可见选项存在，能力不足时静默降级，不向用户解释技术细节。
06 系统状态优先级
优先级条件结果
1（最高）系统「降低透明度」开启整栈强制实体，忽略一切其他设置与容器能力
2app 内「始终使用不透明背景」开启整栈实体，但系统开关关闭时可调回
3容器不能采样背景该容器单独回退到实体基线
4（默认）跟随系统26+ 系统 glassEffect / 15 及更早 .behindWindow + 自绘类液态玻璃层

「增强对比度」只加粗描边与分隔线，不改层级亮度差；「减少动态效果」影响过渡动画，不影响颜色。

07 设置页信息架构（现行 6.1.1）
  • 卡片标题「外观」：自动 / 浅色 / 深色 分段控件（全局生效）+「始终使用不透明背景」开关。
  • 四档材质选择器与「macOS 26 / 27」版本标签已移除；版本适配是实现细节，不出现在设置页。
  • 副标题统一为一句定稿文案：「macOS 26 以前的系统，仪表盘使用类液态玻璃材质；升级到 macOS 26+，自动使用系统液态玻璃材质。」
  • 旧四档译名与版本说明已从设置页移除，版本兼容信息可在「关于」页保留一行。
08 数据与迁移

已采用一次性迁移（AidenteMigration.migrateMaterialPreferenceIfNeeded()：旧 interfaceMaterialStyle: solid → forceOpaqueBackground 开启）。现有偏好是已持久化的用户数据，直接删除会造成升级后外观突变。

  • 首次启动时读取旧值：旧值为「清晰实体」→ 新开关设为开启；其余三档 → 关闭；无旧值 → 关闭。
  • 迁移只执行一次，写入标记后不再读取旧键；旧键保留一个版本周期以便回滚，之后清除。
  • 诊断信息中的「界面材质」字段已改为上报当前生效策略（readabilityStrategy / readabilitySource / forceOpaqueBackground），不再上报档位名。
  • 迁移过程对用户无感，不弹提示、不重置其他偏好。

10 风险与边界
  • 已推翻的早期推断：早期方案曾假设「仪表盘不再透桌面壁纸」。现行方案把仪表盘三个容器的 canSampleBackdrop 恢复为 true，15 及更早走 .behindWindow + 自绘类液态玻璃层，26+ 走系统液态玻璃；因此视觉增量不再是「变平」，而是边缘增厚与三处高光。
  • 26+ 验证缺口（仍在）：系统材质 API 可编译，但实机是 15.8.2；glassEffect(.regular) 与「26+ 不叠自绘层」的分支只能在 26 环境实机核对。另 borderless NSPanel 的 .behindWindow 是否真采到桌面背景也尚未实机验证。
  • 构建约束：部署目标仍是 macOS 14，版本分支必须做可用性门控；项目仍用 swiftc 直接构建，不引入新的包依赖。
  • 早期「不做的事」已部分解除：应用图标已按 Apple 模板重制并补齐 1024 档、状态栏图标已重绘、版本已定为 6.1.1 / Build 22 并输出 Dist/Aidente-6.1.1.dmg；仍保持不加新主题色、不引入第三方材质库。未提交 / 推送 / 打标签 / 发 Release。
