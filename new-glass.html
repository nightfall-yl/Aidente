「毛玻璃」档 · 原样 vs 方案 A

同一个原型可切换两套基准：方案 A（去噪 + 保通透，默认）与改版前原样。前者保留仪表盘透桌面的玻璃，删掉自绘渐变、渐变描边与整体透明度，层级改用固定中性色阶，并按本轮 B 让仪表盘底栏透空、只留 1pt 顶边线；后者逐层还原「可读性策略」重构之前那版 .glass 毛玻璃档。控制条里可随时 A/B 对照，亮暗同样可切。

二 · 方案 A 与还原说明

00 方案 A · 去噪 + 保通透

思路：材质只负责氛围，层级交给中性色阶。保留仪表盘透桌面这一点通透感，把所有为了「让层次看得见」而自绘的渐变、描边、阴影和整体透明度删掉。控制条切到「改版前 · 原样」可逐项对照。

项改版前原样方案 A解决什么
窗口底渐变公共对角渐变 white .34 → jade .025 → black .025；设置页另有垂直 white .35 → black .02整段删除，只留均匀底色同一卡片左右亮度漂移、正文对比度不稳
卡片层级信号底色 + 渐变描边 + 阴影 + 内部分隔线，四重底色抬升 + 1pt 中性描边，仅一个信号「group 组黑框」的框感
整体透明度顶栏 .98，页脚再 .72全部删除；半透明只作用于背景层，内容 alpha = 1文字与图标跟着变淡
仪表盘底栏（本轮 B）页脚有 #EDEDED @ .98 × .72 背景层，是一条浮在玻璃上的浅色带背景整层透空，只留 1pt 顶边线，L0 玻璃直接透上来底栏与自身窗口底天然同色；不用固定中性色去撞会随桌面变化的玻璃
L4 页脚控件三个方块只有 1px 边框，在彩色玻璃上偏淡只给控件本身加极淡半透明底：亮 white .24、暗 white .055按钮可辨，但底栏仍透空、不引入整条色带
层级色值两端各抄一套、随档位变化固定中性色阶，单调递增：亮 #F4F5F6 / #F8F8F8 / #FCFCFC，暗 #232326 / #28282B / #2D2D31L1 > L0、L2 > L0 恒定，L1/L2 两端同值
设置页 L0透明 NSWindow 里 .behindWindow 采样不足，退化成灰自动实体，色值取仪表盘玻璃的平均落点不假装能虚化；并排不突兀
次级文字系统 .secondary 叠在半透明卡片上卡片改实体后对比度可控，无需特判浅色下低于 4.5:1 的风险

刻意保留：仪表盘 L0 的玻璃模糊（这套 UI 最值钱的部分）、L3 强调卡的语义渐变（层级契约里唯一允许 tint 的层）、四档 Picker 的信息架构（A 只动观感，不动架构）、桌面背景与容器能力差异。把状态色收成竖条、把玻璃限制在 L0 属于上一轮优化案 B / C，不在这里。注意本页出现两个「方案 A / B」编号：本轮的 B = 底栏透空，上一轮的 B = 玻璃只铺窗口底，两者不是一回事。

换算到代码是 8 处：删 standardBackdrop 的公共 LinearGradient；删 lightSettingsBackdrop 的 .glass 垂直渐变；AidenteCard 的 strokeBorder(LinearGradient) → 单色 1pt；.shadow(...) → 无；AidenteChromeBar 与页脚的 .opacity() → 只包背景；L0/L1/L2 换成本表的固定色值；仪表盘页脚背景改 Color.clear，只保留 1pt 顶边线；页脚按钮（L4）加极淡半透明底，明暗各一个常量。不改 AidenteReadability、不改偏好迁移、不改容器标志。

01 还原基准

「改版前」= 可读性策略重构之前的工作区状态，即已经落地「浅色方案 B」「液态玻璃设计语言对齐」「Arcan 压边 + Reduce Transparency」「卡片近白化」之后、尚未删除四档选择器的那一版。不是 fork 原版 HEAD：原版浅色卡片走 .regularMaterial，而改版前已按当时那轮「方案 A」改成实体近白 0.985。注意区分：那轮的「方案 A」指卡片近白化，与本页「方案 A · 去噪 + 保通透」是两个不同方案，只是编号撞了。

本原型只还原 .glass 毛玻璃 一档；高斯柔化、液态玻璃的分支不在范围内。系统「降低透明度」按关闭处理。

04 与改版后的差别
  • 材质层数：改版前窗口底带公共对角渐变、顶栏带整体 .98 与页脚 .72、卡片带渐变描边与半透明；改版后全部收敛成一组固定实体色值，无渐变、无模糊、无整体透明度。
  • 两端一致性：改版前亮色下设置页是实体近白、仪表盘是透桌面的玻璃；改版后两端同类层同值。
  • 用户可选项：改版前是四档分段选择器（本原型固定选中「毛玻璃」）；改版后是「跟随系统」+ 一个不透明覆盖开关。
  • 代价：改版后仪表盘不再透桌面壁纸，浅色整体更平。这正是上一轮方案里列为「最大视觉变化」的一条。
05 边界
  • 本文件是视觉还原原型，不是产品代码；没有改动任何 Swift 文件，也没有重新构建 app。
  • CSS 的 backdrop-filter 只能近似系统材质：真实的 NSVisualEffectView 会随壁纸、外观、窗口活跃状态动态变化，透明 NSWindow 里还会退化成系统灰。
  • 卡片渐变描边用 mask 近似 SwiftUI 的 strokeBorder(LinearGradient)；数值按代码 alpha 估算，不追求逐像素一致。
  • 方案 A 的层级承诺有边界：L1 / L2 在两端是固定实体同值，差值恒定；仪表盘 L0 是玻璃，合成色随壁纸变化，所以「L−L0 恒定」只在设置页这条实体基线上严格成立。原型刻意用了彩色桌面把这个差异暴露出来 —— 若希望两端 L0 也一致，需要把玻璃不透明度提高，或改用上一轮优化案 B（玻璃只铺窗口底、卡片全实体）。本轮 B 只解决仪表盘内部的「底栏 vs 窗口底」，不动跨容器关系。
